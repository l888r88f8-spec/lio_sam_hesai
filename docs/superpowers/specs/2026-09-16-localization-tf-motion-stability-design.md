# 行驶中定位 TF 前后抖动：同时间视界试验设计

日期：2026-09-16
状态：待用户复核；尚未实施

## 背景与目标

当前定位直接发布 `map -> base_link`，导航也使用这条 TF；不恢复旧的外部里程计或 `map -> odom -> base_link` 校正链路。用户描述的旧问题是使用外部 odom 时 `base_link` 一卡一卡地大范围晃动，不是本次要恢复的方案。本次症状是稳定化后行驶时前后抖动、静止时不抖。

`hesai_sim` 的现有 `tf-continuity` 回放在 10–30 秒稳定行驶窗口中，101 次外推/回退 TF 到新测量 TF 的切换全部向后跳，中位约 0.075 m；同一窗口 measured-only 轨迹的 106 段没有后退。回放仍报告 `violations: []`，因为现有门禁只检查 TF 时间连续性，不检查空间回跳。该证据定位的是回放中的系统性锯齿，尚不能证明所有实车抖动都只有这一成因。

目标是先做可回滚的离线试验：消除“较新 IMU 外推位姿”和“较早雷达测量位姿被盖上当前 ROS 时间戳”交替造成的系统性前后回跳，同时维持导航所需 TF、现有健康/LOST 语义和原始定位输出。

## 方案选择

1. **推荐：同时间视界发布。** 新雷达结果先按其传感器时刻更新定位锚点，再用该锚点到最新有效 IMU 时刻的段预测；正常 TF 路径始终发布这个最新传感器时视界的位姿，并使用当前 ROS 发布时刻。改动集中在现有预测器、控制器和 `System` 发布边界，可用同一 bag 做前后对照。
2. 关闭 IMU 外推：可作为诊断 A/B，但会使 TF 退化为低频阶梯和处理延迟，不作为导航最终方案。
3. 恢复 `map -> odom -> base_link`：会重新引入用户明确不想使用的旧外部 odom 校正路径，本轮排除。

## 数据流与边界

- `LocalizationResult` 的 `result.timestamp_`、测量 `map_T_base`、path 和 odometry 仍代表原始雷达测量时刻；不把预测值写回定位优化器或伪装成新测量。
- `Localization` 只在成功提交结果后更新现有线程安全预测锚点。`System` 处理新结果时必须验证预测锚点与该结果的传感器时间及 TF epoch 一致；队列合并、超时丢帧或时钟回跳造成不一致时，不得用另一帧锚点冒充当前结果。
- 对于健康且连续的 IMU 段，从测量时刻预测到当前缓存的最新 IMU 时刻，并按现有 `map_T_lidar * lidar_T_base` 和地面高度约束得到 `map_T_base`。正常无新结果的外推路径使用同一个预测/发布规则，而不是一条路径发预测、另一条路径发历史测量。
- ROS TF 的时间戳继续使用当前 ROS 时钟，传感器时间只用于积分、时效判断和诊断；两种时钟不得相减作为位姿年龄。发出的位姿必须对应最新可用的传感器状态，且外推跨度仍受现有 0.5 秒配置上限约束。
- 预测不可用、IMU 断流或超限时，不把旧测量位姿重新当作当前位姿发布。已有 TF 时保持**最后实际发布的位姿**并标记 `held`；首次有效预测前不伪造 TF。`held` 仅保证 TF 图可查询，健康状态/协方差必须继续反映定位陈旧，导航不能把它当作有效运动估计。
- 新测量可能带来真正的配准修正。试验不添加位置低通或任意“禁止后退”钳位，以免掩盖真实运动、重定位和配准异常；若同时间视界后仍有大幅修正，单独分析测量质量与导航安全策略。

## 验证与试验止损

1. 先在控制器/系统边界写失败测试：外推后迟到的新测量不得直接把历史位姿盖上当前 ROS 时间；保持模式冻结最后发布位姿；锚点时间/epoch 不匹配和 IMU 失效时不得使用错误预测。
2. 在 `tf-continuity` 回放门禁中消费已记录的 TF 平移、旋转和原始 odometry 到达事件，计算正常前进行驶窗口的 body-X 位移，以及 `extrapolated -> measured` 边沿回跳。测试应先对旧实现报错，再对试验实现通过；时间间隔、故障注入和恢复契约继续保留。
3. 使用同一个 `/home/robot/rosbag2/hesai_sim` 和相同地图、参数，对照当前基线：系统性 101/101 后跳应消失；正常窗口边沿的后跳中位数不小于 -0.01 m，且不出现大于 0.05 m 的单次反向突跳。这里是该前进行驶 bag 的试验门禁，不是通用车辆倒车限制。
4. `quick`、`tf-continuity`、`tiled-quick`、相关 CTest 和时间回跳/故障模式检查必须通过；测量 odometry/path 的传感器时间与位姿保持不变。若时间连续性、LOST 安全语义或地图模式退化，则试验不进入上车阶段。
5. 不直接在运行导航的实车上验证首版改动。离线全绿后，先静止、低速、再正常速度做记录式验收；比较 TF 运动方向、测量轨迹、处理延迟、健康诊断和导航所见位姿。出现超出离线阈值的跳变或 `held/LOST` 时导航未停用陈旧定位，停止试验并回滚。

## 范围外

不使用车辆轮速里程计或外部 `odom`，不重建 TF 树，不改变配准算法、分块地图、自动重定位策略或地图产物。不承诺单凭去除锯齿就解决所有实车定位问题；离线证据与上车验收分开报告。
