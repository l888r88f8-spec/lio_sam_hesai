# 静止定位 odometry 抖动测量脚本设计

日期：2026-09-17
状态：待用户复核；尚未实施

## 目标与选择

用户已观察到静止时 `/lio_sam/localization/odometry` 的位置也会变化，需要一个可在车上直接运行的 Python 程序量化变化。选择实时订阅该话题，而不是要求先录 rosbag；相比手工 `ros2 topic echo`，程序能对同一采样窗口统一计算指标。脚本只读 ROS 消息，不修改定位节点、TF、参数或地图，也不依赖车轮里程计。

## 输入与输出

- 新脚本放在 `scripts/measure_localization_jitter.py`，依赖 ROS 2 Humble 的 `rclpy`、`nav_msgs` 和 Python 标准库，不引入 NumPy。默认订阅 `/lio_sam/localization/odometry`，从收到第一条有效消息起采集 30 秒；允许用 `--topic`、`--duration` 覆盖。若等待 10 秒仍无有效消息、整个窗口少于 3 条有效消息，或有效样本的首末时间未覆盖至少 80% 的窗口，清楚报错并以非零状态退出。
- 只分析 `pose.pose.position.{x,y,z}`；非有限坐标丢弃并计数。每个采样用本机单调时钟记录接收时间，避免 ROS `/clock` 回跳破坏窗口与漂移拟合；输出有效/丢弃样本数和实际采样时长。
- 每个轴报告峰峰值（max−min）和标准差，单位毫米；水平 `xy` 报告绕均值的 RMS 半径。另分别对 `x(t)`、`y(t)` 做最小二乘直线拟合，报告水平漂移速度（mm/s）和去线性趋势后的 `xy` RMS 半径（mm）。前者描述缓慢移动，后者更接近来回抖动，避免把单向漂移全部算作抖动。脚本只输出观测值，不擅自设定“合格”阈值。
- 用户运行方式：在已加载 ROS 环境、定位节点正在发布时执行 `python3 scripts/measure_localization_jitter.py`；采样期间保持车辆静止。输出可直接贴回对话做诊断。

## 结构与验证

订阅/采样循环与纯统计函数分开，方便不启动 ROS 图也能单元测试。先写失败测试，覆盖恒定位姿为零抖动、已知往复抖动、纯线性漂移被去趋势剔除、无效输入/样本不足；再实现最小代码并跑 Python 单元测试与 `--help`。本轮不做自动录包、不输出 CSV、不估计 yaw，也不根据测量值自动调整任何定位参数。

## 使用边界

这个脚本量化的是 odometry 输出波动，不能单独区分激光配准噪声、IMU 状态估计或真实车体振动。若 odometry 抖动显著，再与同期 `/tf`、`/imu` 和 `reg_fitness` 对照；脚本本身不宣称修复定位。
